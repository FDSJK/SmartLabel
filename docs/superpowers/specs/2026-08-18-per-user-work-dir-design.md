# 按用户隔离工作目录 — 设计文档

> 状态：待用户审阅
> 日期：2026-08-18

## 背景与目标

当前系统只有一个**全局工作目录**：管理员在「系统设置」里设置 `settings` 表 `WORK_DIR`，
所有登录用户共享同一个目录，批次/图像/标注数据彼此可见、不隔离。

目标：把「admin 统一设置全局目录」改为「**每个用户设置自己的工作目录**」，数据按用户隔离——
每个用户只看到自己上传/扫描的批次，看不到别人的。保留集中式后端 + 共享用户体系。

## 关键决策（已与用户确认）

1. **隔离模型**：共享一套 `metadata.db`（用户 / 登录 / 锁 / 设置都在这，登录与用户管理不变），
   仅**数据**（批次、图像、标注文件）按用户隔离。
2. **目录物理位置**：后端部署在局域网服务器上；用户的「工作目录」是**服务器上属于该用户的目录**。
   用户通过浏览器**上传**文件把数据放进自己的目录（浏览器无法直接读用户本机磁盘，已确认接受上传方式）。
3. **目录配置方式**：每个登录用户都能设置**自己的**目录（不再只有 admin 能改全局）。
4. **权限**：只保留一个 `admin` 管理账号；admin 只能新建**标注员**，不能再建管理员。

## 数据模型

- `User` 增加字段 `work_dir: str | None`（可空，存该用户自己的工作目录路径）。
- `Batch`：复用已有的 `created_by`（FK → users.id）作为**归属人**。
  - `Batch.name` 的约束从「全局唯一」改为「**同一归属人内唯一**」：`UniqueConstraint('created_by', 'name')`。
- `Image`：无需改动，通过所属 `Batch.created_by` 继承归属。

## 默认假设（已按推荐取默认值，用户可在审阅时改）

- **A. admin 也隔离**：admin 与普通用户一样有自己的目录、只看自己的数据，仅额外多一个「管理用户」的权限（不额外提供「看全部数据」的监督视角）。
- **B. 用户未设置目录时**：回退到旧的全局设置 `settings.WORK_DIR`（老的单管理员部署行为不变）。

## 后端改动

1. **工作目录解析**：把现在 5 个路由里各一份的 `_get_work_dir(db)` 抽成一个公共函数
   `get_work_dir(db, user)`，解析顺序：`user.work_dir`（若设置）→ `settings.WORK_DIR`（旧全局）→
   `config.settings.WORK_DIR`（env 默认）。调用点全部改用该函数。
2. **数据隔离过滤**：批次 / 图像 / 统计 / 导出 / 扫描 / 上传接口，查询一律加
   `Batch.created_by == current_user.id` 过滤。
3. **新增「设置我的工作目录」接口**：登录用户（含标注员）改**自己的** `work_dir`，只能改自己，不能改别人。
4. **扫描 / 上传**：落盘与扫描都基于当前用户自己的目录（`get_work_dir(db, user)`）。
5. **用户管理权限收紧**：
   - `POST /users`（`create_user`）：去掉 `role` 入参，固定创建 `role="annotator"`。
   - `PUT /users/{id}`（`update_user`）：去掉改 `role` 的能力（不能把标注员提为管理员）。
   - 保证全系统只有一个 admin（启动时创建的 `admin`，无其他创建 admin 入口）。

## 前端改动

- 「系统设置」页：把「全局工作目录」改成「**我的工作目录**」（每个用户设自己的；admin 也设自己的）。
- 「用户管理」页：新建用户不再有角色选择（或固定显示"标注员"）。
- 批次列表 / 数据看板 / 导出等按后端过滤结果展示，无需额外前端逻辑，用户天然看不到别人的数据。

## 迁移与兼容

- 旧数据中 `created_by IS NULL` 的批次，迁移时归给 `admin`。
- `Batch.name` 唯一约束改造：SQLite 下需重建 `batches` 表（新建临时表 → 复制数据 → 删旧表 → 改名）。
- 已有 `settings.WORK_DIR` 保留，作为「未设置目录」用户的回退默认，老部署行为不变。

## 验证

1. 后端：`cd backend && ../.venv/bin/pytest -q` 全绿，新增覆盖：
   - 用户 A 设目录后扫描/上传只落在 A 的目录，列表只返回 A 的批次。
   - 用户 B 看不到 A 的批次（过滤生效）。
   - 未设置目录的用户回退到全局 `settings.WORK_DIR`。
   - `create_user` 无法创建 admin；`update_user` 无法把角色改成 admin。
   - 同名批次在不同用户下可共存，同一用户内重名报错。
2. 前端：`cd frontend && npx tsc --noEmit && npx vite build` 通过。
3. 手工：两个账号分别登录，各自设目录、上传，确认互不可见；admin 建用户时无角色选项。
